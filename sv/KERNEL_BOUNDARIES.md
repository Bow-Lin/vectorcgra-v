# 内核数学、内存回读与完成顺序

本批补齐 AXPY 的实际内存回读，并扩展 GEMM／GEMV 数据和维度边界。
原始 274 个 Python 文件、YAML 和冻结参考不变。程序修复生成到独立目录，
不把原生数学验收标成未修改 Python 的逐周期等价。

## 实际发现与修复

### 无效 STORE 与配对写接口互相等待

此前修复后的 GEMV 在当前原生存储接口停顿：MemUnit 对谓词为假的 STORE 不发送
地址或数据 valid，却仍等待两个 ready；配对内存接口可以合法地等待另一半 valid。
因此这条本应无副作用的指令不能退役。

`tile_memory_fu` 的原生模式现在对 STORE／STORE_CONST 等待所需操作数齐备，
谓词为假时直接消费操作数并退役，不访问内存、不依赖外部写 ready；谓词为真时
仍等待地址和数据同时接受。reset／clear 时不发起原生事务。
`MEMORY_LEGACY_PYTHON=1` 明确保留原行为供兼容重放，参数沿用公共 profile。

32／64 位的两个 opcode，全部谓词组合、输入缺失、四种写 ready、reset／clear，
每组 384 个场景在 RTL 和真实综合网表运行，共 1,536 个场景。
两个网表综合前后及重新读取后的 check／SCC 均通过。错误期望和恢复旧模式都能被检出。

### AXPY 提前返回

原 Python 测试虽然有回读注释，但 `src_query_pkt` 和 `expected_mem_sink_out_pkt`
实际为空。在注册存储模式下，新增检查发现原映射在 **13／16 次写入**时已发出完成包，
最后写入晚 17 个周期。组合存储模式则是最后写入与完成通知同拍接受，属于合法行为。
注册存储的反例说明原映射缺少显式存储完成依赖，单纯匹配原组合存储轨迹不能发现。
检查器按同一时钟沿统一统计写入与完成；另外保留原组合存储程序作为同拍完成的正向检查。

原生程序保留 4×4 布局和原算术工作，将 tile 9 的 RETURN_VOID 改成谓词传递，
沿 **9 → 5 → 1 → 0** 送到存储 PE；tile 0 在 PC4 STORE 退役后的下一轮 PC0
执行 RETURN_VOID。新增 route／FU prologue 对齐第一个实际 STORE，启动前先配置全部新增依赖。
完成包的源 tile 因而从 **9 改为 0**，生成器同时输出对应 `return.hex`。

### GEMV 边界提前返回

消除 STORE 停顿后，1×1 场景又在 **0／1 次写入**时返回。
原生程序将返回谓词沿此前空闲的外围 PE **8 → 12 → 13 → 14 → 15 → 11 → 7 → 3 → 2**
传送到存储 PE。tile 2 在 PC0 STORE 退役后的 PC1 返回；完成包源 tile 从 **8 改为 2**。
中继 PE 只运行一条循环路由指令，避开原算术通路的依赖。

这两项是具体映射程序的修复，不修改 Ret FU 的通用语义；程序打包工具也不会自动修复
任意输入程序。测试没有添加完成后的等待周期来掩盖缺少依赖。
原程序反例及日志见 `reference/current/kernel_boundaries/`，保留旧程序的测试必须明确区分
“最终读值正确”和“完成通知代表所有写入已结束”。

## 验收矩阵

| 程序 | 场景 | 独立期望与写入约束 |
|---|---|---|
| AXPY | 长度 1、2、15、16；原始、全零、正负、高位溢出；系数 3、0、−2 | 原映射 x／y 同址，结果为 `(alpha+1)*input`，模 2³²；每个输出地址恰好写一次；回读全部 32 字 |
| GEMM | n=1、2、3、4；原始、单位矩阵、正负、全零、高位溢出 | `C_initial + A*B`，模 2³²；每个 C 地址写 n 次；回读全部 64 字 |
| GEMV | n=1、2、3、4；原始、单位矩阵、正负、全零、高位溢出 | `A*x`，模 2³²；每个输出地址恰好写一次；回读全部 64 字 |

18 个输入场景各运行组合／注册存储，以及正常／主机背压加配置间隔，共 **72 次整机验收**。
总计检查 **3,840 个内存回读值、1,248 次实际 PE 写入**。输入区、空洞和其它地址预填独立
哨兵值并回读，检查越界或意外改写；在接受完成通知的时钟沿核对全部预期写次数，后续时钟沿禁止继续写入。
每组还检出错误结果、永久背压、额外写入要求；AXPY 注册存储和 GEMV 两种模式分别重放旧返回反例，共 21 次负向检查。
另有 1 次原 AXPY 组合存储的合法同拍写入／完成检查，防止沿前计数导致误报。

原有 GEMM／GEMV 程序另作既有回读回归，不据此宣称其全部维度的完成顺序已经正确。
原有 SPMV（nnz=0…8、正常／背压及五个故障注入）和串行 COO 也在当前 RTL 重跑。
8 个 FU × 539 周期 × 303 位的旧轨迹重放通过，MemUnit／VectorMul 显式选择兼容模式，
Adder 继续使用既有 SUB_CONST-ready 兼容选项。

## 范围和复现

这套夹具仍有明确边界：32 位整数，AXPY 的两个向量同址；矩阵为 n=1…4 方阵，
GEMM 行距为 n，GEMV 行距固定为 4。没有声称支持零长度程序、任意矩形矩阵、任意别名、
通用 DFG 编译或运行时改维度。整机 UNOPTFLAT 诊断仍保留；本批零 SCC 结论仅属于上述两个 FU 网表。

```bash
make -C sv native-kernel-boundaries
make -C sv current-predicated-store current-predicated-store-synth
```

`tests/current/gen_kernel_boundaries.py` 只使用标准库及独立打包工具，读取已冻结的配置；
在 `build/current/kernel-boundaries/fixtures/` 生成程序、返回包、数学期望、写次数和来源 SHA。
94 个生成文件已在独立目录重建并逐字节复核。`run` 模式只允许源码 SHA 与已编译记录一致的二进制。

[validation.json](reference/current/kernel_boundaries/validation.json) 保存每次结果、参数、
源码／工具／日志哈希和范围；[cases.json](reference/current/kernel_boundaries/cases.json)
保存独立输入、预期内存和原生程序修复说明。最终完整系统重新验收在后续批次单独记录。
