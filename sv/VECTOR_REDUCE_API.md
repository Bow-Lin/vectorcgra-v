# VectorAllReduce 的数学与事务契约

`tile_vector_all_reduce` 默认采用修正后的原生语义。单元参数
`LEGACY_PYTHON=1` 保留固定目标 Python 的行为；PE／系统入口通过
`REDUCE_LEGACY_PYTHON=1` 传递此开关，控制器也用它保留旧命令分发。
原 Python 与旧参考 HDL／文本未修改。

## 运算和范围

| opcode | 含义 | 输入 |
|---|---|---|
| 56／57 | 局部加／乘法规约 | 端口 0 向量 |
| 68／69 | 局部加／乘法规约后与 base 相加／相乘 | 端口 0 向量、端口 1 base |
| 76／77 | 全局加／乘法规约 | 端口 0 向量 |
| 78／79 | 全局归约返回值与本地 base 相加／相乘 | 端口 0 向量、端口 1 base |

lane 是无符号数，各中间运算及最终结果按 `DATA_W` 位取模。lane 宽度为
`DATA_W/LANES`；`LANES>=4`、为 4 的倍数且整除 `DATA_W`。
已验收 16/4、32/4、32/8、64/8 四组位宽／lane 参数。
接口固定四输入、两输出，实际只使用输入 0／1 与输出 0；其余输出、存储
接口、常量 ready、结果 bypass/delay 均明确为零。`VECTOR_FACTOR_POWER`
保持原模型的忽略行为；组合 FU 的约束仍要求该参数为零。

## 默认握手

局部运算要求控制有效及所有必要操作数有效，在结果被接收时原子接收操作数并退役控制。
普通运算传递向量 predicate，base 运算取向量与 base predicate 的 AND。

全局运算每次最多一个未完成请求：

1. 请求包含正确的局部和／积、向量 predicate、完整控制字；命令分别为 18／19。
2. 请求握手时接收向量和必要的 base，保存 base 及运算类型。控制仍保留。
3. 等待返回时不重复发请求、不再次接收操作数；返回 ready 受输出 ready 和控制 valid 约束。
4. 结果握手时才退役控制。普通结果使用返回 predicate，base 结果再与保存的 base predicate 相与。

控制源必须在退役之前保持本条控制有效；请求尚未接受时，各参与输入也须遵守
val/rdy 保持契约。返回源在背压期间保持返回数据。结果不会依赖已接收后变化的 base。
不支持乱序返回或多个未完成请求；响应命令匹配由现有控制存储／系统路由负责。

reset 屏蔽握手并清状态。clear 屏蔽握手、取消本地待输出结果；若请求已经发出，
必须排空并丢弃其返回，之后才允许下一请求。当前远端没有取消协议；如果整个批次被
放弃而不会产生返回，需要协调复位控制器／网络，不能仅靠单 FU clear 恢复。

系统控制器默认把命令 19 与 18 一样分发到已有全局归约器，修复原 Python 漏分发
乘法导致的死锁。归约器保留原单批次协议：先配置参与数，参与请求须使用同一操作，
批次不重叠；它有 16 项请求队列。这里没有增加任意参与规模、乱序批次或运行时隔离取消。

## 兼容差异与验收

兼容模式完整保留：乘法请求错误地取加法结果、base 请求缺少控制／重复保护、
ADD_BASE_GLOBAL 缺少 base ready、普通全局结果 predicate 为零、控制提前退役、
返回无视输出背压以及忽略 clear。八个定向用例要求原生通过、兼容模式明确失败。
这将源模型缺陷与迁移偏差分开记录。

```sh
make -C sv current-vector-reduce current-vector-reduce-synth native-global-reduce
```

组件检查包括全部 8 个 opcode 的独立宽整数数学、缺失操作数、长背压、base 捕获、
请求／返回／控制计数守恒、clear 后排空旧返回，以及错误预期负控。四组兼容轨迹共
1,440 周期、459,360 输出位／实现、36 个 reset 采样。四组原生各 8,340 项断言；
八份实际综合网表重新读入 Yosys 检查，零 SCC，并运行相同台架。

端到端用例用四 CGRA、两个归约参与者，在主机背压下核验每轮恰好两个请求、两个
返回、六个完成包。向量为 1…8，base 为 17／−5：加法结果 53／31，乘法结果
685440／−201600（32 位补码）。每种运算都有错误最终结果负控。
旧三组组件 HDL 对照和完整 Python 全局加法周期重播也单独运行。
证据见 `reference/current/vector_reduce/validation.json`。

本项不声称完成四态证明、全系统综合网表、任意网络背压下所有仲裁器的保持证明、
全部系统回归或远端 CI；这些仍按 `MIGRATION_TASKS.md` 后续步骤验收。
