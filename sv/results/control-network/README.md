## 正确性

| 检查 | 本次结果 |
|---|---|
| 单播传输 | 5 种几何 × 原环/平衡/按行，共 15 个参数配置 |
| CONFIG 组播 | 6 种几何 × 两种树，共 12 个配置；含 2×17 的两字掩码 |
| 背压与复位 | 共 54 次正常/背压运行，各含两个复位后有效 epoch；另验证在途部分接收后复位丢弃 |
| 负例 | 107 个，错误期望、非法目的、关闭组播、空/未装完/越界掩码均被正确拒绝 |
| 数学整机 | 136 次完整运行，每次回读全部 32 字；其中 16 次用固定提交的原始 RTL 编译 |
| 原硬件完整消息对照 | 96 次候选运行与固定提交的原硬件结果逐完整包相同；仅允许独立 PE 完成消息交错 |
| 全局归约 | 20 次加/乘运行，实际 PE 请求和 Controller 响应，逐字回读 |
| 连续任务 | 6 次无中间复位运行，每次两个不同归约任务，分别完整回读；共 12 个任务 |
| 静态能力拒绝 | 8 种非法 RTL profile，均以指定错误标记拒绝 |
| 工具/工程检查 | 26 个配置/程序/YAML、8 个组播工具、14 个工程脚本测试通过；274 个原 Python 文件审计通过 |
| 原组件回归 | NoC primitives、router/credit、3 节点 native/legacy 环通过；原 PE 接口 7 个 profile 通过 |

必需几何为 2×2、3×3、4×4、2×3、3×2。矩形传输测试使用大于实际阵列的 MAX 几何；
64 位 2×3 整机也验证该边界。参数传输矩阵不代表所有几何都跑过全系统数学。
同一系统二进制分别加载 `x+17` 和 `3*x+11`，改变算术、路径、常量和输入；
启用组播的同一二进制也运行原单播流，避免用不同硬件混淆阶段 A/B 的收益。

原 RTL 从固定提交提取所有源码和头文件，使用同一新测试台从正常主机口配置；
普通包编码与固定提交的原打包工具逐文件相同。候选原环 2×2/4×4 的周期也与原硬件一致。
测试台对内部状态只有只读观察，没有初始化内部控制/数据存储。

## 周期对照

以下为 **4×4、32 位、组合读存储、`3*x+11`、输入 seed=0、无主机随机停顿**。
两棵树在此几何具有相同分组，运行结果相同。以下使用平衡树展示。
运行中的 payload/FU/内存配置完全相同，每次都进行完整结果回读。

| 指标 | 原环：固定提交 | 树：单播 | 同一树：组播 |
|---|---:|---:|---:|
| 主机总包数（含预加载、回读） | 275 | 275 | 230 |
| CONFIG 逻辑写入 | 96 | 96 | 96 |
| 配置传输包（含掩码） | 96 | 96 | 51 |
| 首配置/掩码接受 → 最后控制存储写入 | 104 | 104 | 59 |
| 首主机包 → 首控制步退役（准备） | 249 | 252 | 207 |
| 首 LAUNCH 主机接受 → 首退役 | 22 | 25 | 25 |
| 首 → 末控制步退役（计算跨度） | 96 | 96 | 96 |
| 首主机包 → 收齐 COMPLETE（任务） | 354 | 355 | 310 |
| 首 PE 返回接受 → 末主机 COMPLETE | 25 | 23 | 23 |
| 结果读请求 → 最后读响应 | 224 | 224 | 224 |
| 驱动总周期（含回读与尾部观察） | 610 | 611 | 566 |

51 个配置包 = 21 个掩码设置 + 21 个组播 CONFIG + 9 个普通 CONFIG。
96 次目标控制存储写入完全保留。这里只统计明确声明的同一配置批次，没有跨常量/启动阶段合并。

表中跨度按 `末事件周期 - 首事件周期 + 1` 计算；区间可以重叠，不能直接相加。
驱动原日志输出的是从零开始的最终 cycle 下标，JSON 同时保留该值和加一后的实际周期数。
复位不计入运行跨度，预加载计入准备/任务时间，回读计入驱动总时间。
尾部观察的原驱动条件是最终输出周期后继续到 `done+32`。

这一用例中，单播树没有缩短任务时间，启动到首次退役还多了 3 周期；
其作用主要是减小传输结构。组播使同一树少发送 45 个包，任务和驱动分别减少 45 周期。
计算跨度没有改变。这个结果不能外推为任意程序都减少 45 周期。

## 资源对照：通用综合，未布局布线

工具：Verilator 5.029、sv2v 0.0.13、Yosys 0.45+139。
Yosys 使用 `synth_xilinx -family xc7 -flatten -noiopad -noclkbuf`，
仅综合独立控制网络，全部 payload、单播目的和背压仍为可变输入。
同一规模的所有方案使用 DATA_W=32、CTRL_DEPTH=6、REG_DEPTH=5、NUM_BANKS=4、BANK_DEPTH=8，
HOST_BITS 从该几何一致推导；没有固定程序、删除 FU 或改变计算位宽来制造差异。

| PE 几何 | 后端 | 逻辑 LUT1…6 原语数 | FF 原语数 | RAM32M 原语数 |
|---|---|---:|---:|---:|
| 2×2 | 原环 | 10,955 | 460 | 1,085 |
| 2×2 | 平衡/按行，单播 | 695 | 88 | 435 |
| 2×2 | 平衡/按行，组播 | 716 | 93 | 435 |
| 3×3 | 原环 | 19,810 | 924 | 2,170 |
| 3×3 | 平衡，单播 | 1,838 | 218 | 1,063 |
| 3×3 | 按行，单播 | 1,844 | 218 | 1,063 |
| 3×3 | 平衡，组播 | 1,868 | 228 | 1,063 |
| 3×3 | 按行，组播 | 1,863 | 228 | 1,063 |
| 4×4 | 原环 | 37,079 | 1,576 | 3,808 |
| 4×4 | 平衡/按行，单播 | 3,468 | 400 | 1,988 |
| 4×4 | 平衡/按行，组播 | 3,490 | 417 | 1,988 |

上述 15 个独立综合全部通过 `check -assert` 和无组合环的 `scc -expect 0`。
DSP、BRAM、SRL 在这些控制网络配置中均为零。**RAM32M 是占用 LUT 的分布式存储原语，
不能忽略，也不能把一整个 RAM32M 直接视作一个 LUT。** 表中逻辑 LUT 原语数不是实现后的总 LUT。
完整单元分类及网表散列保存在 [synth.json](synth.json)。

当前没有实际器件、XDC、Vivado、布局布线、setup/hold 或 FPGA 板卡运行记录。
因此这些计数只支持“该独立控制结构在相同通用综合条件下更小”的结论，
不提供整个 CGRA 的 LUT 节省百分比、最高频率或两种树的物理最优排序。
整机编译仍有基线数据路由/寄存器路径的 `UNOPTFLAT` 警告；无组合环检查只针对独立控制网络。

## 重现与证据

完整运行命令见 [设计文档](../../CONTROL_NETWORK.md#6-可复现执行与验收)。
统一入口：`make -C sv current-control-network` 和 `make -C sv current-control-network-synth`。
单次实验的可执行文件、程序和原始轨迹留在忽略的 `sv/build/control-network/`；
本目录只保存紧凑 JSON 和测试日志集合，不提交编译对象、二进制、转换 RTL 或综合网表。

```bash
python3 sv/tests/control_network/collect.py --input sv/build/control-network
python3 sv/tests/control_network/collect.py --check
```

统一 make 入口的输出位于 `sv/build/current/control-network`，导出时相应改用该 `--input`。
`manifest.json` 固定已验源码及证据散列；`logs.json` 按相对构建路径收集正例和指定负例的原始日志。
`validation.json` 是总索引；其他同名 JSON 对应各 runner，保留参数、边界指标、退出码、
输入程序/二进制/轨迹/完整消息的散列。原始完整消息比较允许跨 PE 完成次序变化，不要求逐周期一致。

过程中的问题均未计为通过：首次负例被复位丢弃而未检出，已修正注入时机；
检查器曾混用未规范化的零默认字段；首次重复任务误把 LAUNCH 当作状态清除，
后改为基线合法的累计步数/预装常量流程；构建缓存曾因 PCH 占满磁盘中断，清理对象后重跑。
旧尝试的日志和报告保留在构建目录中。本目录记录最终通过的数据，未修改原实现来掩盖这些现象。
